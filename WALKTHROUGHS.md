# Walkthroughs

Step-by-step, copy-pasteable instructions for turning your own team's project into StudySpot's equivalent - one file per lecture, each assuming the previous one's steps are already done.

- [WALKTHROUGH-01.md](WALKTHROUGH-01.md) - From a Blank Computer to a Running Project (Lecture 01): install prerequisites, scaffold the ASP.NET Core + React template, get it running.
- [WALKTHROUGH-02.md](WALKTHROUGH-02.md) - Full CRUD, Swagger, and a Create-Session Form (Lecture 02): add `PUT`/`DELETE` to the API, wire up Swagger/OpenAPI docs, add a real UI form for creating a session.
- [WALKTHROUGH-03.md](WALKTHROUGH-03.md) - Validating Input, Client and Server (Lecture 03): add client-side form validation, prove it's not enough by bypassing it with a direct API call, then add server-side model validation, a small CSS pass, and repository process artifacts (pull request template, definition of done, CONTRIBUTING.md, CODEOWNERS).
- [WALKTHROUGH-04.md](WALKTHROUGH-04.md) - C# Language Features, and a Real Timezone Bug (Lecture 04): add a `record`, an `enum`, an extension method with an optional argument, LINQ filtering, and `IComparable<T>` sorting - then fix a real wall-time bug by switching `StartsAt` from `DateTime` to `DateTimeOffset`.
- [WALKTHROUGH-06.md](WALKTHROUGH-06.md) - SOLID in Practice (Lecture 06): split a do-everything controller into a controller, a service (Single Responsibility), and a repository behind an interface (Dependency Inversion), wire them up with Dependency Injection, and see why every implementation of the interface has to honor the same contract (Liskov).
- [WALKTHROUGH-08.md](WALKTHROUGH-08.md) - Automated Tests, then async/await and Cancellation (Lecture 08): split the repository into an API folder and a React folder, add an xUnit v3 test project next to them with unit tests, a fake repository, controller tests with NSubstitute and `WebApplicationFactory` integration tests, frontend tests with Jest and React Testing Library in their own folder, and one coverage report for both - then make the repository, service and controller async with a `CancellationToken`, using the tests as a safety net. The same API tests also exist in NUnit and MSTest, for comparison.

- [WALKTHROUGH-09.md](WALKTHROUGH-09.md) - A Real Database with Entity Framework Core, then Concurrency Conflicts and a Custom Exception (Lecture 09): store sessions in SQLite through a `DbContext` and a second implementation of the repository interface, create and apply migrations, run the integration tests against their own database - then add a version to every session so a conflicting edit throws a custom `StudySessionConflictException`, handled once for the whole API by an `IExceptionHandler` that returns `409 Conflict`.

From Lecture 08 on, the API lives in `CoolApp.Api/` and the React app in `CoolApp.Client/`, with the test projects next to them; earlier walkthroughs describe paths from before that split, when the project sat at the repository root and the React app in `ClientApp/`.

These are separate from [README.md](README.md) and [ROADMAP.md](ROADMAP.md), which describe *this* repository's own product decisions (StudySpot) - the walkthroughs are reusable instructions meant for **your own team's project**, without the StudySpot theming.
